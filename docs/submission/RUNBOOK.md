## Локальный запуск: шаги для репетиции

1. Сверить наличие `Dockerfile`, `compose.yaml`, `.dockerignore`, `.env.example` и фиксированных версий зависимостей: `<TBD_FROM_TG030>`.
2. Создать локальную конфигурацию по `.env.example` и получить секреты вне репозитория: `<TBD_FROM_TG030_TG034>`.
3. Выполнить предусмотренную архитектурой команду `docker compose up --build`. Фактическую команду, необходимые профили и результат запуска записать: `<TBD_FROM_TG030_TG034>`.
4. Проверить readiness, миграции, seed и адрес локального UI/API: `<TBD_FROM_TG030_TG034>`.
5. Открыть путь через **реальный MAX** по инструкции `<TBD_FROM_TG033_TG034>`; прямой браузерный URL не подменяет эту проверку.
6. Пройти [DEMO_SCRIPT](DEMO_SCRIPT.md) с тем же Case ID и проверить второй проход на новом DemoRun. Протокол репетиции: `<TBD_FROM_TG034>`.
7. Остановить стек командой `docker compose down` и повторить запуск; сохранение Case, истории, вложений и очереди проверить по протоколу `<TBD_FROM_TG030_TG034>`.

Команда `down -v` удаляет том БД и **не** относится к обычной остановке/повторному запуску. Конкретные порты, переменные окружения, требуемые версии Docker и поведение ошибок: `<TBD_FROM_TG030_TG034>`.

## Проверка публичного экземпляра

Проверить TLS/HTTPS, доступность бота и Mini App в MAX, вход из мобильного и веб-клиента, webhook, реальное сообщение после Result, соответствие `build_sha`, сохранность после рестарта, восстановление подписки и повтор доставки. Для каждого пункта использовать запись из [EVIDENCE_INDEX](EVIDENCE_INDEX.md), а не предположение по локальному E2E. Публичный адрес и временное окно доступности: `<TBD_FROM_TG032_TG034>`.
