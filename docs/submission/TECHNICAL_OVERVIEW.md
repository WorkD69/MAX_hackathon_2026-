# Технический обзор — заготовка для TG-034

> **PREP ONLY.** Этот документ описывает утверждённый проект и места для будущих доказательств. Он не подтверждает реализацию, развёртывание или прохождение проверок. Финальные утверждения допускаются только после сверки с TG-032, TG-033 и финальным артефактом.

## Продуктовый контур

По [Product Freeze](../01_PRODUCT_FREEZE.md) и [Product Spec](../02_PRODUCT_SPEC.md) основной путь объединяет жителя, УК и подрядчика УК в **одном Case**: обращение, принятие УК, передача и приём подрядчиком, координация доступа, результат, проверка жителем, замечание и доработка при необходимости. Администратор УК управляет настройками и правами внутри стороны УК. Демонстрационный случай: неаварийная неисправность внутридомового стояка отопления, по которой УК уже приняла организацию работ. Правило ответственности для любой проблемы с отоплением из этого не следует.

Нормативные верхнеуровневые состояния Case: `Создано` → `Принято УК` → `Передано подрядчику` → `Исполнение` → `Ожидается проверка результата` → `Замечания рассматриваются` → `Доработка` → `Завершено`. Это перечень восьми состояний, а не обещание линейного перехода через каждое из них: после подтверждения результата возможен путь к завершению, а доработка образует цикл того же Case. Назначение, комментарии и результат фиксируются отдельными фактами истории; их нельзя объявлять дополнительными верхнеуровневыми состояниями.

## Утверждённая архитектура и статус реализации

Согласно [Technical Architecture](../03_ARCHITECTURE.md), целевая схема: бот MAX открывает одну responsive Mini App на React/Vite; Fastify API на TypeScript исполняет команды и проверяет права; PostgreSQL хранит Case, историю, вложения, DemoRun и очередь уведомлений; узкий серверный MAX adapter связывает Bot API и webhook. Это **архитектурное решение**. Фактически поставленные компоненты и версии: `<TBD_FROM_TG029_TG030>`.

Один Case и его история — серверный источник истины. `DEMO_MODE` предназначен для тестовой демонстрации четырёх ролевых представлений и не равен production IAM. Синтетические данные в демонстрации должны быть обозначены как синтетические; фактический состав seed: `<TBD_FROM_TG008_TG034>`.

## MAX и граница доказательств
