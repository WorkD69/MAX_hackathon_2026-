# Кратко о проекте

Строим сервис в MAX для жителя квартиры в многоквартирном доме: один случай проходит от обращения через УК и подрядчика до проверки фактического результата. Приоритетный демонстрационный случай — неаварийная неисправность внутридомового отопления, для устранения которой подрядчику нужен доступ в квартиру.

Три стороны процесса: **житель** сообщает о проблеме и проверяет результат; **УК** принимает и координирует случай; **подрядчик УК** принимает поручение и выполняет работу. Администратор УК управляет настройками внутри стороны УК.

MAX — среда основного проверяемого сценария. Утверждённый объём включает **Bot + Mini App**. Ключевой механизм: **«подрядчик сообщил о выполнении» ≠ «проблема решена»**. Житель может оставить замечание; УК рассматривает его и возвращает **тот же case ID** на доработку без новой заявки. События и результаты остаются в одной карточке.

Масштабирование предусмотрено через конфигурацию домов, категорий, подрядчиков и связей между ними на общем жизненном цикле, без отдельного программного процесса для каждой категории.
